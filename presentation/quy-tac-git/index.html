Quy tắc Git

Mọi nhánh merge vào develop. Chỉ lead nhóm được merge develop → main.

feature · fix · chore → develop

Qua PR, ít nhất 1 người duyệt.

develop → main

Chỉ lead nhóm, khi đạt checklist ổn định.

hotfix → main → develop

Tạo từ main, merge ngược về develop.

1Merge develop → main

Chỉ lead nhóm · cuối sprint hoặc trước demo · tick đủ 6 mục mới được merge.

Còn 6 mục chưa đạt. Chưa được merge.
git checkout main && git pull origin main
git tag v0.1 && git push origin v0.1   # bàn giao là v1.0

2Đặt tên nhánh

Viết thường, không dấu. FE và BE luôn tách nhánh.

3Gộp nhiều use case

Được gộp khi đủ cả 4

  • Cùng nhóm UC
  • Cùng một người
  • Dưới 400 dòng
  • Xong trong 3–5 ngày

Không gộp

  • Khác nhóm UC
  • FE với BE
  • UC lớn: POS-02, 03, 04, STK-01, 04

Mỗi UC một commit riêng.

4Quy trình làm task

git checkout develop && git pull origin develop
git checkout -b feature/auth-01-03-be-xac-thuc
git commit -m "feat(auth-01): đăng nhập"
git pull origin develop                       # trước khi tạo PR
git push origin feature/auth-01-03-be-xac-thuc  # rồi tạo PR vào develop

5Commit

<loại>(<mã-uc>): <mô tả>, ví dụ feat(prod-01): thêm API tạo sản phẩm

feat tính năngfix sửa bugrefactor sửa codestyle formatdocs tài liệutest testchore cấu hình

Cấm: update, fix bug, final2.

6Pull Request

  • Dưới 400 dòng, ít nhất 1 người duyệt, không tự duyệt.
  • Review trong 24 giờ: đúng use case, đúng API contract, không lộ key.
  • Squash and merge, merge xong xóa nhánh.
  • Conflict thì người tạo PR tự sửa; đụng code người khác thì hỏi trước.

7Điều cấm

  • Push thẳng main / develop
  • Merge feature thẳng vào main
  • Không phải lead mà tạo PR vào main
  • push --force lên nhánh chung
  • Commit .env, mật khẩu, key
  • Commit node_modules, build, dist
  • Nhánh sống quá 5 ngày
  • Sửa migration đã merge
